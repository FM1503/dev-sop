dev-sop：开发 SOP 门禁

让 AI 像专业工程师一样先问清需求、查证方案、线框确认、量化验收，再动代码。

七阶段工作流程

  1. 1

    需求澄清访谈

    AskUserQuestion 分至少 2 批提问（每批 ≤4 问），覆盖功能、外观、非功能、边界与验收；首批答复后同轮先发 WebSearch——调研与访谈并行。
    产出：结构化需求列表
    禁止臆测
  2. 2

    联网调研

    WebSearch / WebFetch 查证成熟案例与技术选型，关键结论附来源链接。
    产出：调研结论 + 链接
    来源必附
  3. 3

    规格文档

    全文呈现于回复中，经 AskUserQuestion 选项批准（批准 / 需修改 / 放弃）。
    产出：docs/specs/<slug>.md
    status: approved
  4. 3.2

    UI 数据表 + 线框

    涉及界面时：组件清单表 + ASCII 线框，≥2 方案用 preview 供用户选择。
    产出：spec 内 UI 章节
    wireframe: approved
  5. 3.5

    任务书

    目标文件、期望行为、验收标准、测试要求，委派 prompt 必须引用其路径。
    产出：docs/tasks/<slug>.md
    解锁委派
  6. 4

    TDD 实现

    先写测试确认失败，再由 code-worker 执行代理实现到全绿。
    产出：测试 + 业务代码
    主会话不写码
  7. 5

    量化验收 + 对抗自审

    UI 用 ui-analyzer / lvgl-check 单次委派自动闭环（采集→分析→修复→复测，≤5 轮 / 10 分钟）；与独立审查同消息并发，增量由主会话快检。
    产出：<slug>.ui-report.json
    error = 0

五把硬钥匙

status: approved

spec frontmatter 标记，解锁业务代码文件的写入。

wireframe: approved

spec frontmatter 标记，解锁 UI 文件（.html/.css/.vue/LVGL .c 等）的写入。

<slug>.ui-report.json

docs/specs/ 下量化验收报告，全部 error=0 才允许结束交付（Stop 钩子）。

<slug>.test-report.json

docs/specs/ 下验收测试报告，records 全 pass、failed=0 才允许结束交付（Stop 钩子）。

<slug>.review-report.json

review: required 任务的独立审查报告，verdict 为 pass 或 pass-with-issues（后者须经用户确认定稿）才允许结束交付（Stop 钩子第五把钥匙）。

组件清单

组件作用
hooks/gate.jsPreToolUse 门禁：无批准 spec / 线框时拦截写入与委派
hooks/inject.js检测开发意图，自动注入流程提醒
hooks/accept-check.jsStop 门禁：强制 UI 量化验收、验收测试报告与 review: required 审查报告（verdict 为 pass 或 pass-with-issues，后者经用户确认）通过才可交付
hooks/ui-collect.js浏览器内采集页面几何数据（多视口）
hooks/ui-analyzer.mjs量化分析：越界 / 重叠 / 44px 点击区 / 对比度
hooks/lvgl-check.mjsLVGL 源码静态量化校验
references/design-rules.md内置设计规范（硬规则 + 软指导）
agents/code-worker.md执行代理：只执行不决策的唯一编码角色
agents/reviewer.md审查代理：独立上下文只读四维审查，产出 review-report.json（第五把钥匙）
commands/spec.md/spec 命令入口
